# タングラム研究室

小学校算数の面積指導を中心とした、教員の教材研究用Webアプリです。HTML・CSS・JavaScriptのみで動作し、実行時の外部ライブラリ・ビルドは不要です。初期表示時のみ、既存教材アプリと共通のGASへアクセス記録を送ります。通信できなくても教材機能は利用できます。

公開予定URL: https://handson-matsu.github.io/tangram/

## 起動と公開

リポジトリ直下を静的HTTPサーバーで配信します。

```sh
python3 -m http.server 8000
```

ブラウザで `http://localhost:8000/` を開いてください。ES Modulesを使うため、`index.html` のファイル直接起動（`file://`）は対象外です。

GitHub Pagesではこのリポジトリのルートを公開対象にしてください。サブパス `/tangram/` で動く相対URL構成です。`.nojekyll` を含みます。今回の実装では公開設定の変更、コミット、プッシュは行っていません。

## 操作方法

### 共通操作

- ピースをドラッグして移動します。マウス、タッチ、ペンをPointer Eventsで扱います。
- 選択ピースのそばにあるボタンで左右45度回転・反転します。回転の中心は面積重心です。反転は重心を通るローカルの縦軸で行い、回転・反転で重心位置は動きません。
- 矢印キーで0.1単位、Shift＋矢印で0.01単位移動。Q / Eで左 / 右回転、Fで反転します。
- Undo / Redoボタン、またはCtrl / ⌘ Z、Ctrl / ⌘ Shift Zで履歴を操作します。モードごとに最大150状態を保持します。
- 「初期配置」は現在選んでいるピースを離して並べ直します。Undoで戻せます。
- スナップは0.18座標単位以内で働きます。頂点同士を優先し、頂点→辺、辺→頂点への平行移動も候補にします。内部が重なる候補は除外します。精密な移動にはスナップをオフにしてください。
- ドラッグ中だけ内部の重なりを許し、赤い枠で示します。無効な位置で離したら、ドラッグ中に最後に確認された有効位置へ戻ります。操作がキャンセルされた場合は開始位置へ戻ります。
- 作業台の外には確定できません。回転・反転が無効になる場合も操作を戻します。
- 作業台では `touch-action: none` とポインターキャプチャを使い、意図しないスクロールを抑えます。作業台以外は通常どおりスクロールできます。

### 自由制作・問題作成

チェックボックスで2〜7枚を選びます。ピース数と面積を常時表示します。全体が離れている状態も制作途中として保存できます。

内部の重なりがなく、全体が連結したら「シルエット問題に登録」を押します。点だけの接触も連結です。パズルモードに移り、色の境界線を消した黒い問題を表示します。「7枚の正方形を並べる」で標準の分割配置も観察できます。このボタンは7枚すべてを使用する配置に変更します。

### シルエットパズル

登録した問題と同じピースで黒い領域を覆い、「完成を判定する」を押します。元のピース配置とは異なる別解でも、領域が一致すれば正解です。問題と解答は同じ座標上で比較します。全体をずらしたり回したりしただけでは、元の黒い領域と一致しない限り正解になりません。

「元の解答を見る」は確認用の重ね表示です。閉じると自分の解答に戻ります。表示中はピースを編集できません。

最新の登録問題をブラウザ内に保持します。複数の問題を保管する場合は、それぞれJSONで保存してください。問題JSONを読み込むと自由制作で編集を再開でき、パズルモードではその問題に挑戦できます。

### 正方形チャレンジ

2〜7枚を選び、好きな向きの正方形を作って「完成を判定する」を押します。向きは判定条件にしません。成功した配置をJSON保存すると、完成正方形として保存され、読込後はこのモードに復帰します。未完成の配置は制作途中のJSONとして保存され、自由制作で再編集できます。

6ピースなどの不可能性は自動判定しません。

## 保存と読込

- **JSON保存**：使用ピースID、重心位置、45度刻みの角度、反転、タイトル、状態種別を記録します。
- **JSON読込**：2〜7枚・ID重複なし・有限な座標・45度刻み・型・作業台内・内部非重複を検証します。完成問題には連結、完成正方形には正方形判定も適用します。不正なデータは作業状態を置き換えず、エラーを表示します。
- ファイルは100KB以下、タイトルは100文字以内。`eval`・HTML挿入は使いません。
- **シルエットPNG**：黒い領域を白い背景に保存します。重なりがなく連結した作品のみ対象です。
- **配置PNG**：色と境界線を含む配置を白い背景に保存します。
- パズルモードのJSON・両PNG保存は、問題と元の解答配置が対象です。解答中の配置はブラウザ内の自動保存で保持します。
- ブラウザのlocalStorageにモードごとの最新作業と最新問題を自動保存します。Undo履歴と一時的な解答表示は再起動後に引き継ぎません。ブラウザ設定等で自動保存できない場合はメッセージを表示します。大切な作品はJSONでも保存してください。
- ダウンロードしたファイルの保存先やiPad上の保存操作はブラウザによって異なります。

サンプル問題: [examples/square-problem.json](examples/square-problem.json)

### JSON形式（バージョン1）

```json
{
  "format": "tangram-lab",
  "version": 1,
  "kind": "draft",
  "title": "面積の研究",
  "pieces": [
    {"id": 5, "x": 8, "y": 8, "angle": 0, "flipped": false},
    {"id": 6, "x": 13, "y": 8, "angle": 0, "flipped": false}
  ]
}
```

`kind` は `draft`（制作途中）、`problem`（連結した問題）、`square`（完成正方形）。ID 0〜6は順に大三角形A・B、中三角形、正方形、平行四辺形、小三角形A・Bです。

## 数学的な実装方針

### 正確な標準形状

一辺4の正方形を標準の7ピースに分割した整数座標を元データとします。小三角形の面積を1として、面積は `[4,4,2,2,2,1,1]`、合計16です。各ピースを面積重心に対するローカル座標として保持し、反転と回転の剛体変換を適用します。反転後は頂点の向きを反時計回りに統一します。

大三角形の直角を挟む辺は `2√2`、中三角形は `2`、小三角形は `√2`。正方形の辺は `√2`、平行四辺形の隣接辺は `2` と `√2`、角度は45度・135度です。

### 内部の重なりと接触

凸多角形の**分離軸定理（SAT）**を使います。両方の多角形のすべての辺の単位法線へ射影し、区間を比較します。

- いずれかの軸で区間が離れる → 非接触
- 離れる軸がなく、いずれかの軸で区間が接する → 境界接触
- すべての軸で区間内部が交わる → 内部の重なり

このため頂点同士、頂点と辺、辺の全部・一部の共有を許し、頂点が辺上にあっても内部が重なる配置は拒否します。単なる頂点包含や線分交差だけで判定していません。

### 連結性

境界接触しているピースを辺で結んだ無向グラフを作り、全頂点を探索できるか確認します。点接触も接続とする通常の連結性です。制作途中は非連結でも許し、問題登録時は連結を必須にします。

### シルエットの和集合と別解判定

問題領域は各ピースの多角形領域の和集合です。描画は反時計回りの全多角形を**1つの複合パスにまとめてnonzeroルールで塗りつぶし**ます。境界線を描かず、点接触・T字の接触でも輪郭を1本の単純多角形へ無理に変換しません。PNGも同じ複合パスで一度に塗ります。

判定はラスタ画像や外接矩形ではなく、連続座標の多角形面積で行います。問題も解答も内部非重複であることを確認したうえで、各凸多角形の組をSutherland–Hodgman法でクリッピングして交差面積を合計します。

```
対称差の面積 = 問題の面積 + 解答の面積 − 2 × 交差領域の面積
```

各集合の内部で重複しないので、交差面積は全ピース対の交差面積の和で求められます。これが0なら和集合は面積として一致します。閉じた非退化な多角形の有限和に対して適用し、ピースの対応や頂点数には依存しません。点接触による複数輪郭や穴も、領域として同じ方法で扱えます。

### 正方形判定

内部非重複を確認し、全頂点の凸包から同一直線上の中間頂点を除きます。凸包が4頂点、4辺が等長、隣接辺が直交し、さらに**凸包面積とピース合計面積が一致**するときのみ成功です。これにより内部の穴・隙間、単なる正方形の外接矩形を除外します。

### 数値誤差と制約

JavaScriptの倍精度浮動小数点数を使います。正規化した射影区間の接触許容差は `1e-8` 座標単位、面積比較の許容差は `1e-7` 小三角形単位です。正方形の等辺判定は `1e-7` 座標単位です。

厳密な有理数・代数的数の演算ではないため、この許容差以下の微小な隙間・侵入を区別しない場合があります。面積判定を画面の見た目に合わせて緩める実装ではありません。実用上の配置は頂点・辺スナップで整えます。スナップの探索先には問題を構成した全ピースの頂点・辺も含めますが、正誤判定は元の分割配置を要求しません。

## テスト

Node.js 20以降で、追加インストールなしで実行できます。

```sh
npm test
# または
node --test
```

HTTPサーバー起動後、[tests/browser.html](tests/browser.html) を開くと、**Node.js版と同一の幾何・状態テスト**をブラウザでも自動実行できます。

検証内容と結果の詳細は [TESTING.md](TESTING.md) に記載しています。実機iPad / Safariのタッチ・ファイル保存は未検証です。

## ファイル構成

- `index.html` / `style.css`：日本語画面とレスポンシブ表示
- `app.js`：操作、モード、履歴の接続、自動保存、SVG・Canvas描画、ファイル処理
- `access-counter.js`：既存教材アプリと共通のGASアクセス記録
- `camera.js`：表示倍率・全体表示・表示移動（ピース座標から独立）
- `geometry.js`：標準形状、剛体変換、SAT、クリッピング、連結・領域・正方形判定、スナップ
- `state.js`：履歴、JSONスキーマ検証
- `tests/cases.js`：Node.jsとブラウザで共有する自動テスト
- `tests/geometry.test.js` / `tests/browser.html`：各実行環境のテストランナー
- `examples/square-problem.json`：読み込んで編集・出題できるサンプル

ピース一覧のアイコンは実際の形状データを共通縮尺で描画し、面積比も示します。正方形・シルエットの正解時には、作業台の下にチェック付きの大きな緑色の成功表示が現れ、次の操作まで維持されます。


## 作業エリアのズーム・表示移動

- 初期表示倍率は従来の135%。「＋」「−」で拡大・縮小でき、範囲は35〜500%です。
- 「全体表示」は現在の使用ピースすべてを余白付きで収めます。横長・縦長の作品にも対応し、パズルでは黒い問題領域も含めます。
- 「初期倍率」は135%へ戻し、作品全体の中心に表示位置を戻します。拡大中に一部が見切れたときは「全体表示」で探せます。
- 余白のドラッグで表示位置を動かせます。「表示を移動」をオンにすると、ピースの上でも表示移動を優先します。ピースを動かすときはオフにしてください。
- 表示はモードごとに独立して保持します。表示操作はUndoの対象外で、再読込時には初期倍率になります。
- 点線は従来の20×12の配置可能範囲です。ズーム・表示移動はこの範囲やピースの座標、形状、面積、判定、JSONに影響しません。
- PNGは表示窓のスクリーンショットではなく、作品全体を座標から描画します。画面外のピースも含み、倍率に依存しません。


## アクセス記録・カウンター

`../triangle-tiling/src/access-counter.js` と `../hexagon-tiling/src/access-counter.js` を照合し、アプリ識別子以外は同じ処理を使用しています。

- GAS URL：`https://script.google.com/macros/s/AKfycbxssCIHsD-N97SHxNC_GN0ihYeC0qy-lb-EY0KmSs6Gnztaph1sITMerLVEnNWOGkYc/exec`
- 送信：`GET`、クエリ `app=tangram`
- オプション：`mode: 'no-cors'`、`cache: 'no-store'`、`credentials: 'omit'`、`keepalive: true`
- `app.js` の初期化末尾から文書につき1回だけ呼び出します。同じ文書内のモード切替、移動、回転、反転、選択、履歴、ズーム、保存・読込では追加送信しません。
- ブラウザの再読み込みでは新しい文書になり、改めて1回送信します。ユーザー単位・日単位の重複排除ではありません。既存アプリと同様、ローカルサーバーから通常画面を開いた場合も送信します。
- 同期例外・非同期通信失敗を内部で処理し、再送しません。GAS応答を待たずに描画・操作・保存を続行します。
- 独自の送信パラメータはアプリ識別子のみです。作品タイトル、ピースの配置、読込JSONは送信しません。
- 既存2アプリに画面上の件数表示はなく、GASへの記録を優先する同じ構成にしました。`no-cors` の不透明な応答からアクセス総数や実際の保存結果は取得できないため、カウンターは表示しません。

### アクセス記録の検証

`npm test` は従来の幾何・状態・カメラ52件、アクセス5件、既存2アプリとのソース完全一致2件を実行します。隣接リポジトリがない環境ではソース比較2件のみスキップします。

- `tests/browser.html`：共有自動テスト57件。通信関数をモックし、実GASへは送信しません。
- `tests/access-browser.html`：本番HTML・本番モジュールをiframeで実行する統合テスト18件。通信成功・非同期失敗・同期例外の各条件で、初回1回、実際の再読み込みで新たに1回、操作中の追加送信なし、JSON・PNG生成と操作の継続を確認します。GAS通信とダウンロード起動をテスト側だけで差し替え、実GASにテスト記録を作りません。

開発時の結果と検証限界は [TESTING.md](TESTING.md) に記載しています。GASの実行ログ・保存先には接続していないため、サーバー側の記録保存結果は未確認です。
